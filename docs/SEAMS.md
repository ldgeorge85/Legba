# Seams

This page lists the parts of Legba that are deliberately not built, and what the
code does when something reaches one. It is for contributors, and for admins who
see an error or refusal that names a seam.

The rule: production code under `src/legba/` holds no stubs or mocks. Anything
not built is declared here. At its guard the code raises an error, refuses to
activate, or writes nothing. It never produces made-up output.

`tests/test_no_undeclared_stubs.py` enforces the rule. It scans `src/legba/**`
for stub markers: a `NotImplementedError` raised with a message, a symbol named
stub, fake, mock, placeholder or echo, a mock import, or an empty return next to
a TODO. Each hit must be either the abstract-method idiom or a line in the
[machine-readable allowlist](#machine-readable-allowlist). There is no per-line
escape, so declaring the seam here is the only way past the test.

Adding a seam takes two edits in this file: a row in the table below and, if the
code trips the scanner, a `src/legba/<path>.py:<dotted.symbol>` line in the
allowlist. Removing the code removes both. The test also fails on an allowlist
line whose symbol no longer exists.

## Seam ids

Code and docs cite a seam as `SEAMS #<id>`. An id is never reused. A resolved
seam keeps its id and moves to the [resolved seams](#resolved-seams) table.

Seams 1 to 94 have numbers. A new seam takes a short lower-kebab slug instead
(for example `email-imap-mailbox`), cited as `SEAMS #<slug>`. Its row goes after
the numbered rows in alphabetical order, and its allowlist lines go under a
`# seam <slug>` comment. With slugs, two changes that each add a seam do not
edit the same line. `tests/test_seam_ids.py` checks the rules: numbers stay at
or below 94, and slugs are unique, well formed and sorted.

Rows 46, 55, 60 and 61 also feed the console's Accuracy page.
`scripts/gen_not_published.py` copies each row's title, the first two sentences
of "What is not built" and the first sentence of "Guard" into
`legba-ui-v3/src/lib/not_published.json`. After editing one of those rows, run
the script and commit the JSON; `tests/test_gen_not_published.py` fails while it
is stale.

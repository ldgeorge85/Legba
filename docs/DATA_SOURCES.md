# Data sources

A **source** is a declared connector that acquires observations. It owns its own
acquisition: a `SourceActor` turns a `SourceDescriptor` into a running actor that
polls on a cadence or receives a push, produces one canonical, target-agnostic
**signal**, enriches it once, and publishes it once. Signals carry no target —
the fan-out plane routes each one to every subscribing target by predicate, so
one polled feed serves every target that wants it without re-fetching anything.

This page is for deciding **what to register**: the scope model, the handler
kinds available, the editorial and licence classes a descriptor declares, which
sources need a credential, and how to add one. For how a feed becomes a signal —
the actor, the poll and push protocols, the handler contract, baseline
enrichment, dedup, subscription and the evidence archive — see
[ACQUISITION.md](ACQUISITION.md). Live counts are generated into
[RELEASE_STATE.md](RELEASE_STATE.md) and are never repeated here.

## The scope model

"How many sources?" has three honest answers, because three different things are
being counted. Anchor every scope claim to one of them.

**The tree** is what the repository carries: every `descriptors/source_*.yaml`
file, plus the entries of the active profile's source catalog
(`profiles/<id>/rosters/source_catalog.yaml`; the example profile is
`profiles/geopolitics`). Every file ships `state: draft`, which is the safety
property that makes bulk registration harmless: **a draft registers but gets no
live actor**, so a whole batch can land in the registry and still poll nothing
until each feed is verified live and transitioned `draft → configured → active`.

**What a deploy registers.** `deploy/deploy.sh` runs one registrar,
`scripts/bringup_register_descriptors.py --profile <dir>`, which registers every
descriptor file and catalog entry of the profile, minus the rows of
`descriptors/RETIRED.md`, and walks each head to the state the profile's
lifecycle overlay records (`descriptors/LIFECYCLE.md`, with per-descriptor notes
under `descriptors/LIFECYCLE.d/`), or leaves it at its shipped `draft` when no
row names it. The overlay is the reference deployment's record of which feeds it
switched on; a different instance carries its own. The walker is idempotent: a
re-run reports unchanged heads. It also seeds host-level `source_credibility`
rows from each source batch with `ON CONFLICT DO NOTHING`, so an admin's
override or an earlier seed always wins. A descriptor can also be registered by
hand through the lifecycle route, one at a time.

The descriptors on disk keep reading `draft` after activation, and that is the
intended shape: the repository ships the safe default, and the registry's
lifecycle state records each activation. The live head is authoritative over
the file, always.

**The live scope** is what is actually registered and polling on a given
instance. It is generated by `scripts/generate_release_manifest.py` into
[RELEASE_STATE.md](RELEASE_STATE.md), as a live query against the registry
broken down by kind, and must not be quoted as a literal anywhere else: it moves
with every activation, pause and retirement. Two adjacent numbers are not feeds
and should not be added to it: sources that are paused or retired keep the
signals they already produced, so a count of distinct sources that have ever
emitted exceeds the active-registered count; and autowired per-target fan-out
templates (`src_autowire*` / `src_tmpl*`) are generated bookkeeping, not
upstreams.

The source catalog's loader (`scripts/bringup_register_source_catalog.py`)
records in its docstring the feeds that were probed and deliberately kept out
(dead, blocked or discontinued); re-probing before re-adding one is the point of
the record.

### What a batch is for

Batches exist because breadth is a collection decision, not a code change. Two
shapes recur, and both are chosen from a measured gap rather than a hunch:

- **A coverage pass.** A target goes quiet, a read-only count on the live
  signals table confirms no local outlet is registered for it, and a batch
  registers the outlets that would cover it (in the example instance: a country's
  state press agency, a high-volume independent outlet and a regional station).
- **A domain batch.** A thematic family of targets needs trade press and primary
  sources (in the example: a canal authority, an IGO's trade-measures feed, a
  semiconductor trade title), tagged so those targets' predicates match them.

One batch uses a different mechanism worth naming. Many credible regional,
government and major-media outlets publish no usable feed, so the worst-covered
targets stay thin no matter how many global wires are polled. A self-hosted
**RSSHub** sidecar bridges a chosen outlet route into a standard feed the
existing `rss` handler polls — breadth with no new source kind. The sidecar runs
behind its own compose profile, so a plain `up` never starts it; it is
loopback-bound and memory-capped; and because the `rss` handler's egress guard
blocks internal hosts, activating one of those descriptors also requires the
sidecar on the runtime's egress allowlist. The registrar seeds credibility rows
for the **upstream outlets**, never for the bridge, because the feed's article
links are the real outlet URLs.

## Source kinds

The runtime discovers handlers structurally: it walks `legba.data.sources` and
collects `kind → handler class` pairs from `_SOURCE_MODULE_TABLE`
(`src/legba/runtime/source_factory.py`), which the registry in
`src/legba/data/sources/kinds/` fills. **Twenty-two** first-party kinds are
registered today: the eighteen `kinds/core.py` declares and four plug-in kinds
(`page`, `portwatch`, `series_api`, `stream_json`), verified against the
handlers' own `kind` class-vars
(`cat src/legba/data/sources/*.py | grep -c 'kind: ClassVar\[str\]'`) and
pinned by `tests/runtime/test_ingestion_sinks.py`. The table below covers the
general-purpose kinds; `page` (the page pipeline behind on-request fetching, see [operations/on-request-fetching.md](operations/on-request-fetching.md)) and `portwatch` are not in it.

Every poll source declares `cadence.schedule` on its descriptor — that is the
tick. The window column below is the handler's own config knob for how far back a
single pull reaches; where it is blank, the handler is purely cursor-driven.
Credential references in config are **vault refs** — a dotted credential id,
never a raw secret — resolved at call time and never cached past one pull.

|---|---|---|---|---|
| `rss` | poll | any RSS 2.0 / Atom 1.0 feed | `cursor_lookback_hours`, `first_poll_max_entry_age_days` | The broadest surface and the reference handler. Honours conditional GET: stores `(ETag, Last-Modified)` and sends `If-None-Match` / `If-Modified-Since`, so a 304 is an empty pull. No auth. The factory imports each module defensively, so a missing optional dependency
logs and skips that one kind rather than poisoning the whole registry.

## The source class

Every `SourceDescriptor.scope` carries a **`source_class`**: the source's
editorial class, so the analysis plane can weight a claim by *what kind of source
made it* rather than only by host credibility. The vocabulary is a closed literal
in `src/legba/data/schemas/source.py`, defaulted to the conservative `reporting`
bucket so every descriptor written before the field existed still validates.

| `source_class` | Meaning |
|---|---|
| `reporting` | Straight news and wire reporting — the default, and the "when unsure" bucket |
| `analysis` | Research and data projects, think-tanks, OSINT collectives, coded-event datasets |
| `official` | Government, IGO and primary-source publishers |
| `state_media` | State-controlled outlets, read as **framing** — an official-position signal, low-tier for establishing facts |
| `claim` | A party's **own claim** — a group saying it did something, or a tracker listing what groups posted. Supports only "X claimed Y" (see [Claim sources](#claim-sources)) |

Two consumers read it. The `narrative_coordination` unit weighs `state_media` as
framing rather than fact, which is the whole reason state-media feeds are
deliberately ingested rather than excluded: the desk needs to see what a party to
a conflict is claiming. And the hourly salience sweep turns the class into a
signal's deterministic `authority` rank — `official` 4, `reporting` 3, `analysis`
2, `state_media` 1, and 0 for a source with no resolvable class — never
model-chosen. A source reached outside a registered descriptor therefore falls to
the honest authority floor rather than borrowing one. The `collection_gap` analyst uses the
same taxonomy to name which class would plausibly feed a starved desk.

**Per-channel override.** One class per descriptor is the right granularity for a
feed and the wrong one for a descriptor fronting many publishers. A
`telegram_channel` descriptor may therefore carry an optional `config.classes`
map from channel handle to `source_class`, which the salience sweep prefers over
the descriptor's own class. Without it, appending a state outlet to a monitor
classed `reporting` would launder official media into neutral reporting for every
downstream consumer. Three properties keep the map from becoming a second place
for truth to drift: it is choice-locked to the `SourceClass` vocabulary, so an
off-vocabulary value fails at registration; a validator rejects any key that is
not a configured channel, so a typo fails loud instead of quietly overriding
nothing; and handles are normalized identically on both sides, so a match cannot
be missed on formatting.

A related distinction is kept deliberately: state-**funded** but editorially
conventional public broadcasters stay `source_class: reporting` with a
state-affiliation flag on the credibility row. Honest provenance and editorial
independence are two different facts, and collapsing them would mislabel both.

### Claim sources

Some sources carry a party's own claim rather than a report of an event: a
group announcing that it attacked someone, or a tracker listing what such
groups posted. Such claims are often exaggerated, recycled or invented, so the
platform enforces in code what a claim can support. It does not rely on the
wording of a prompt.

**Declaring one.** `scope.source_class: claim` together with a `scope.claim`
block (`src/legba/data/schemas/source_claim.py`). The block names the
**claimant**:

- `claimant` is the declared name a row is attributed to. For a tracker, this
  is the tracker itself ("ransomware.live listed ...").
- `claimant_path` is optional: a dotted path into the row's payload where the
  feed names the claimant per row.
- `claimant_aliases` is optional: other ways the claimant is written ("NJ Team"
  for "Nightjar"); the attribution check accepts any of them.

The claimant is taken from that structured field when the field is present.
Otherwise it is the declared one. A model never chooses it. `verb` is the
reporting verb for the supported sentence: `claimed`, `posted` or `listed`.

The schema refuses the class without the block, and refuses the block on any
other class. A claim source is text only and never a fact source, so these
are also refused when the descriptor is saved:

- a `fact_extractor` stage;
- a `follow` policy;
- `pipeline.media: eager`;
- a media object store;
- any sink family other than `document`.

**One Telegram channel as a claim source.** The shared Telegram descriptor
can mark a single channel `claim` in `config.classes`; the channel then needs
its own declaration in `config.claims.<channel>` (the same block as
`scope.claim`: claimant, optional `claimant_path` and aliases, verb,
sign-off). The channel's rows follow every rule on this page (stamp, text
hygiene, no fact extraction, no link following); the descriptor's other
channels are unchanged. A descriptor with a claim channel may not declare a
follow policy or media retain, and cannot be `active` while any claim channel
lacks its own `sign_off`.

**The ingest stamp.** The source actor stamps a claim row before enrichment,
and the document sink writes the stamp again at the write:
`payload.claim = {source_class, claimant, claimant_from, verb}` (plus
`aliases` when declared, and `channel` for a Telegram claim channel). It
removes any media reference from the row. It also removes a claim-shaped key
that a non-claim row's feed carried, because a feed cannot classify itself.

**The text a claim row keeps** (`src/legba/data/claim_hygiene.py`, applied
before enrichment). Every URL is reduced to its host (`[link: example.net]`);
an onion address to `[onion link]`; the row's own address is kept only on the
source's own host and otherwise becomes `claim-item:<hash>`. Email addresses,
phone numbers, government-id-like and payment-card-like numbers, IBANs, street
addresses where the pattern is reliable, and credentials become their kind
(`[email]`). Runs of file names or record lines become `[lists N files]` /
`[sample data: N rows withheld]`. Organisation names are kept. Names of
private individuals are NOT redacted: code cannot tell them apart reliably,
and a source whose posts name private people is a source not to switch on.
The counts (never the values) are on the poll's provenance row,
`source_poll_outcomes.claim_hygiene` (migration 0265). The raw fetch is still
kept as the receipt; its stored text is shown only to admins and the
platform's own services (`claim_support.claim_text_withheld`).

**What a claim row can support.** The rules live in `src/legba/data/claim_support.py`.
Each code path that turns a signal into support reads the stamp.

| Path | Rule |
|---|---|
| Verify floor (`provenance/verify.py:_deterministic_floor`) | A citation of a claim row supports a sentence only when the sentence presents the claim as a claim (`data/claim_attribution.py`): a clause carries an attribution frame bound to the claimant ("Nightjar posted ...", "according to the group's leak site ...", "listed by ...", in six languages) and no other clause states the event, through a factive verb ("confirmed", "revealed") or a presupposition ("the stolen files"). Otherwise it fails as `claim_as_fact`: soft and counted unless `LEGBA_VERIFY_CLAIM_AS_FACT=hard`. On the labelled test set (`tests/data_pkg/fixtures/claim_attribution_set.psv`, invented sentences) no event statement passes, at the cost of a few fair sentences flagged. |
| Composition floor (`_deterministic_floor_subclaim`) | A composition citation of a read that rested ONLY on claim rows carries the claim stamp (`hop: 2`, `source_independence.stamp_cited_head`), and the same check applies. |
| Judge evidence view (`provenance/judge_evidence.py`) | A claim citation is prefixed `CLAIM ONLY: ...`. |
| Fact write path (`provenance/writes.py:_insert_fact`) | A fact whose only lineage is claim rows, or reads that rested only on claim rows, is refused (`ClaimOnlyFactRefused`) unless its predicate is about the claim (`claimed`, `posted`, `listed`, ...). Claim rows are never a fact's credibility input (`max_signal_credibility`). |
| Fact extractor (`filters/fact_extractor.py`) | Refused when the descriptor is saved. At runtime a claim signal also passes through unextracted. |
| Independence (`analysts/source_independence.py:independence_of`) | A claim citation is never an independent source. |
| Event promotion and counts (`_event_candidates.py`, `event_clustering.py`, `_event_lifecycle.py`) | A claim member never counts toward the two-source bar or `distinct_source_count`. An event evidenced only by claims is declined (`claim_only`). |
| Edge qualification (`analysts/edge_qualification.py`) | Claim rows are not counted as independent support. |
| Source track record (`source_track_record.py`) | Claim rows are not an input to wins, losses or corroboration. |
| Institutional salience lift | Never applied to a claim. |
| Contrary pass (`_contrary_fences.py`) | A page on a claim host has `host_class: claim` and counts toward nothing (migration 0258). |
| Open-question bearing (`claim_watch`) | A claim row may still bear on an open question (the claim is news about the question), and its edge says so: `bearing_edges.data` carries `evidence_class: claim` and the claimant. |

**Links are never followed.** No claim source has a follow policy, and the
follow step returns early for one. The intake refuses an address request whose
parent signal is a claim row, or whose follow source is a claim source, with
`claim_link_refused`. The only exception is a target host that is the address
host of an ordinary (non-claim) registered source. The evidence archiver never
selects a claim row.

**Presentation.** In an analyst's slice, a claim row carries a
`CLAIM by <claimant>` line. The feed roster block names claim rows apart.
`GET /signals` rows carry `evidence_class: claim` and `claimant`. A finding's
judgment-weight citations carry `claimant`. In the console, a cited claim
row's chip reads `claim · <claimant>` instead of `signal`.

**Sign-off before activation.** A claim source cannot go `active` without
`scope.claim.sign_off: {by, at, note}` recorded on the descriptor: the
instance owner's sign-off per source or channel, made with the owner's own legal
position and the platform's terms in view. The lifecycle route
answers 409 `claim_sign_off_required` without it. The descriptor model refuses
an `active` claim body without it, so a registration or PUT cannot bypass the
route.

**What ships.** Two example descriptors: `source.ransomware_live.claims` (the
ransomware.live RSS feed) and `source.ransomlook.claims` (the RansomLook RSS
feed). Both carry a recorded sign-off and ship `state: draft` like every other
file. Neither declares a claimant field: every row is attributed to the tracker. Vendor hacktivism and DDoS
reporting is not this class; it ships as ordinary `reporting` sources. How
to switch a claim source on, what you will see and what is refused:
[operations/claim-sources.md](operations/claim-sources.md). What the class
still does not do is listed in SEAMS #82 and #91.

## Licence and robots

Legba fetches what it is allowed to fetch, and says so per host rather than
assuming.

**Licence is a declared field, not an inference.** `SourceScope.license_class` is
a closed literal (`public_domain`, `open_gov_attribution`, `cc_by`, `cc_by_sa`,
`cc_nc`, `open_data_sharealike`, `permissive_feed_unreviewed`, `tos_restrictive`,
`personal_use_only`, `api_terms`, `anti_ai_walled`, `unknown`), defaulting to
`None`. `None` is honest absence — never reviewed — and is deliberately distinct
from `unknown`, which is a reviewed "we looked and could not determine" verdict.
When set, the ingest path copies it onto every signal's payload, where the corpus
facet and the evidence archiver's retention gate read it.

For hosts reached outside a registered descriptor, the same verdict lives on the
per-host **licence ledger**: a `license_class` column on the admin-curated
`source_credibility` table, which is already a per-host ledger keyed the same
way and reviewed by the same person. A second host table would
have given one host two homes and two review surfaces. The column has no check
constraint, because the vocabulary grows with the ledger's review passes and a
constraint would turn every addition into a migration; the vocabulary is enforced
in code instead, and an unrecognised value resolves to the shallowest fetch depth
— the fail-safe direction.

The gate that reads it **fails closed**. A web-origin row whose `license_class`
is unset or `unknown` is not archived: the hit lands as a signal with its
snippet, and no bytes are retained. An affirmative class clears full-text depth
and a content-addressed archive; a refusing class means the page is never fetched
and no row is written at all. The migration that added the column seeds **zero**
verdicts, on purpose: classifying a host is a legal reading, and the platform
will not have a model make one. Until an admin reviews a host, the full-text
path is empty by construction rather than by accident.

**Robots** are obeyed by the one handler that crawls. The `scraper` handler
fetches each host's `/robots.txt` once per host, caches it, and skips any
disallowed URL; `respect_robots` defaults to `True`, the same user agent is used
for the robots fetch and the crawl, and a robots fetch that fails downgrades the
handler's health to degraded rather than silently proceeding as if permitted. The
feed handlers do not crawl — they fetch a published feed URL the publisher
offers for that purpose.

Per-source licence terms that constrain use are recorded where the source is
declared and repeated in the kinds table above: ACLED is non-commercial, UCDP is
CC BY 4.0 with attribution required on re-export, and OpenSanctions' high-volume
path is the self-hosted mode for licence compliance. A feed whose own terms
allow only non-commercial reuse (a CC BY-NC licence, or a government's
non-commercial reproduction grant) is stamped `cc_nc`. That is a
licence obligation, not a read restriction, so such a feed keeps `access_class:
public` (rule 1 below) — the same treatment as an API whose terms reserve
commercial reuse (`api_terms`).

## Access class

`SourceScope.access_class` answers a question `license_class` does not: not
*what may we keep of a fetched page*, but **who, inside a Legba deploy, may
read what this source produces once it is in our own substrate.** A single
deploy can carry units or users with very different privileges — or need them
kept apart for research and testing — and this is the mechanism for that, not
enforcement of it yet (see `docs/SEAMS.md` #59). The vocabulary is a closed
literal in `src/legba/data/schemas/source.py` / mirrored in
`src/legba/data/provenance/access.py`, defaulting to the **fail-closed**
`restricted` bucket — never `public` by implicit default, unlike
`source_class`'s conservative-but-open `reporting` default.

| `access_class` | Meaning |
|---|---|
| `public` | No restriction — any unit/user with substrate read access |
| `licensed_commercial` | A paid, commercially-licensed feed — read gated to units covered by that licence |
| `licensed_noncommercial` | Free-for-noncommercial-use — read gated to noncommercial units |
| `restricted` | Reviewed-sensitive, or simply never classified (the fail-closed default) |
| `internal` | The instance's own staff only |

**The classification rule, applied to every committed `source_*.yaml`:**

1. **Default `public`** — a free, no-auth, openly-available feed. No separate
   commercial-licence agreement gates internal read access, so any unit may
   read what it produces. This is the large majority of files, including
   every wire/newspaper RSS feed, every government/IGO primary
   source, every state-media voice, and UCDP GED (CC BY 4.0 is
   attribution-only on re-export — an obligation `license_class` carries, not
   a read restriction).
2. **`licensed_noncommercial`** — a curated dataset carrying its OWN
   noncommercial-bounded reuse terms, distinct from open-web reporting:
   ACLED (non-commercial licence; a paid one is required for commercial
   redistribution) and OpenSanctions bulk + API (default tier CC BY-NC; the
   self-hosted high-volume mode exists specifically for licence compliance).
3. **`restricted` (fail-closed)** — a never-bound generic or template
   adapter with no concrete editorial source to review terms for:
   `common_crawl_news`, `discord_webhook`, `firecrawl`, `generic_webhook`,
   `query_source_discovery_template`, and the page pipeline
   (`page_pipeline_default`, which fetches whatever address a request
   names). Each is a draft binding with no live actor, classified at
   activation rather than guessed now.

The per-file verdict is pinned, taxonomy-test style, in
`tests/data_pkg/test_access_class_taxonomy.py::EXPECTED_YAML_ACCESS` — the
same discipline `source_class`'s `EXPECTED_YAML_CLASS` is held to, including
the completeness guard that fails a future `source_*.yaml` landing
unclassified.

**The ingest stamp.** `runtime/source_actor.py:write_canonical_signal` copies
the writing source's `scope.access_class` onto every signal's own
`access_class` column (migration 0216, `NOT NULL DEFAULT 'restricted'`) — the
same shape the `license_class` payload stamp uses, but a first-class
column rather than a payload key. A backfill in the same migration recovers
existing rows from their source's registered head.
Sign-in roles (reader, contributor, admin) do not read this column yet; access
class is a stored label, not an enforced boundary.

**The inheritance rule, rendered but not wired.** A fact/finding/event is as
restricted as the most restricted signal it derives from —
`access_ceiling_sql()` in `data/provenance/access.py` renders that as one SQL
expression (single-hop over `derived_from`, mirroring `origin.py`'s
`live_gate_sql`), for the enforcement side to pick up later. Nothing in this
tree calls it today.

**The opt-in filter.** The `/signals` and `/findings` read routes
(`data/registry/substrate_reads_api.py`) accept `access_class_in=<csv>`.
Absent, every read is byte-identical to before this pass; present, `/signals`
filters its own `access_class` column and `/findings` matches when any
signal in a finding's `derived_from` carries one of the requested classes.
"Accept but never apply by default" is the whole of what this pass builds —
see SEAMS #59 for what is deliberately still missing (a caller identity or
unit to check the filter against).

## Credentialed opt-ins

The out-of-box catalog exercises only the keyless kinds. Everything below needs a
per-deployment secret in the vault before it polls, and each is registered as its
own descriptor rather than through a batch. None polls until an admin
provisions the secret and transitions the descriptor. The in-tree descriptors ship `draft` for exactly
this reason, and their headers carry the flip instructions.

| Opt-in | What it needs | Shape of the commitment |
|---|---|---|
| Telegram | API id, API hash and a session, all vault refs; the session is generated out of band | An account-bound client. One descriptor per session. |
| Firecrawl | API key | Paid and credit-metered; every pull writes a credit-usage record to the budget ledger. |
| MediaCloud | API key | Free tier with rate limits the handler backs off against. |
| Discord | the application's Ed25519 public key | Push — an inbound webhook, verified per request. |
| GDELT via BigQuery | a GCP service account | Scan-billed. The per-pull byte cap and optional daily budget are what keep it bounded. |
| OpenSanctions | none for bulk; an API key for the drill-down mode; a base URL for self-hosted | The bulk mode needs no credential at all. |
| IntelMQ | per-bot configuration, plus infrastructure | Needs an IntelMQ deployment and optionally the Redis bridge, not just a key. |
| ACLED | API key and the registered email | Non-commercial licence; commercial use needs a separate one. |
| UCDP | a free registration-gated access token | Free to obtain; the handler degrades cleanly to no poll without it. |
| Residential proxies | a `proxy_pool` stack component | Optional, and only for the `scraper` kind, which references it as a stack ref and takes an optional proxy country. |

## Adding a source

Registering a source is a deploy-time step, not a code change: the live source
set is the registry's descriptor rows, not the files on disk.

A descriptor is one YAML document with five blocks:

```yaml
identity:                # id, name, kind, schema_uri, version, state, owner, created
  id: source.example.world
  kind: rss
  state: draft           # registers without a live actor; an admin activates it
scope:                   # what target selectors match against
  owner_tenant: shared
  geo: []                # omit for a global feed; a target narrows per signal
  languages: [en]
  tags: [news, world]
  classifications: []    # optional: [<family>:<value>] of registered families
  source_class: reporting
  license_class: permissive_feed_unreviewed
acquisition: poll        # or push
cadence:                 # poll only — one poll for the whole platform
  schedule: { factory_kind: cron, raw: "*/15 * * * *" }
  cooldown_seconds: 60
  jitter_seconds: 30
config:                  # validated against the handler's own config_schema
  url: { factory_kind: text, raw: "https://example.org/feed.xml" }
pipeline:                # ingestion filters, baseline enrichment, media policy
  media: reference
```

**Declaring what the stream is.** `scope.classifications` names
the source's classification as `<family>:<value>` tags of REGISTERED vocabulary
families (`sanctions.programme:ofac_sdn`, a profile's `<profile>.<axis>`, or a
platform family). Registration refuses a family the registry has not loaded by
name, then an unknown value of a loaded one — register the family's rows first.
Every signal the source writes then carries the declared keys in its own `tags`
(where a target's `scope.signal_tags` slice finds them) and the bound entries in
`signals.data.classifications` (with the legacy `scope.tags` as `src:`; see
[DATA_MODEL.md](DATA_MODEL.md) *Source-declared classification*). `scope.tags`
stays what it was: free selector tags, which may now also be namespaced. A
profile's source catalog declares it per feed with the same key
(`classifications:` on a `rosters/source_catalog.yaml` entry). Omitted, nothing
about the descriptor or its content hash changes.

The descriptor also carries `subscription_policy` (`open` | `allowlist` |
`grant`), which gates who may subscribe to it; see
[ACQUISITION.md](ACQUISITION.md) for how that is enforced.

The lifecycle is the same for every family. Register with
`POST /api/v1/registry/descriptors/{family}`, then move it with
`POST /api/v1/registry/descriptors/source/{id}/transition` through
`draft → configured → active`, pausing and resuming through the same route and
retiring through `/retire`. The Source Registry panel drives all of it from the
console (see [UI.md](UI.md)), and [RUNBOOK.md](RUNBOOK.md) has the procedure.
Register the feed as `draft`, verify the route live on the instance — a wrong
field path makes a handler emit nothing and report unhealthy, never fabricate —
then activate.

Adding a source needs no code. The existing kinds reach most upstreams, the
predicate fan-out wires the new feed to every target whose selector matches it, and
nothing downstream is edited.

## Adding a source kind

A kind is a drop-in. There is no central list to edit beyond one table entry.

1. **Write a handler class** in a new module under `src/legba/data/sources/`,
   satisfying the `SourceHandler` protocol from `_contract.py`. Declare the
   class-vars `kind`, `family = "source"`, `schema_version` and `config_schema`.
   There is no base class to inherit — the contract is a runtime-checkable
   protocol, so structural conformance is enough and a handler can be tested
   without a runtime.
2. **Pick a mode.** A poll source implements `pull(ctx, since)` yielding signals;
   a push source implements `ingest(ctx, body, headers)` and sets
   `push_source = True`; a kind that can serve `acquisition: subscribe`
   implements `parse_event(ctx, event, stream_url=, transport=)` (one received
   event to its records — the connector owns the connection). All implement
   `health_check(ctx)`. A source that must
   register an outbound watch upstream also implements `on_activate` /
   `on_retire`.
3. **Define a pydantic `config_schema`** with `extra="forbid"`. Store credentials
   as vault references and resolve them at pull time; validate filters at config
   time so a bad descriptor fails fast rather than at the first poll.
4. **Yield signals, not enriched rows.** Set the observation-side fields only —
   modality, payload, canonical URL, language hint, and a media *reference* rather
   than bytes — and leave language, geo, tags, entity classes and credibility to
   the baseline. Persist a cursor in the state store, and treat `since` as a
   hint: downstream dedup absorbs the overlap window.
5. **Register the module** by adding one `(module, class)` tuple to
   `_SOURCE_MODULE_TABLE` in `src/legba/runtime/source_factory.py`. The factory
   inspects the constructor signature and threads in only the dependencies the
   handler declares.

Once registered, an admin can author a descriptor of that kind, the actor
schedules it, the baseline enriches its signals and the fan-out routes them — no
other code changes.

## Subscribed sources

Some upstreams do not wait to be asked: they emit records as they happen,
over a connection the reader keeps open. A **subscribed** source
(`acquisition: subscribe`) is Legba holding that connection. It is the fourth
way a source delivers, beside `poll` (a reminder wakes the actor and the
handler pulls), `push` (the upstream POSTs to the webhook front) and the
intake's `request`, and it lands on the same spine: the same handler kinds
parse what arrives, the same sinks write it (documents to signals, typed
records to their family's sink), the same fetch receipts keep the bytes, and
each window of the held connection writes the same `source_poll_outcomes` row
a poll writes, so a subscribed source shows in the same health and firing
views as a polled one. No workflow engine is involved.

**The connection protocol is an option per source.** The `subscribe` block
names it and carries its settings plus the bounds every transport shares:

```yaml
acquisition: subscribe
subscribe:
  transport: sse                   # built: sse. websocket / nats: refused at save (SEAMS #78)
  url: https://stream.example.org/v1/stream
  headers: {}                      # static, non-secret
  auth: {header: Authorization, secret_ref: source.example.stream_token, value_template: "Bearer {secret}"}
  event_types: [message]           # SSE event types to keep (empty = all)
  resume: last_event_id            # or none: every reconnect is a declared gap
  idle_timeout_seconds: 90         # no byte for this long = a stall
  backoff_initial_seconds: 1       # full-jitter exponential reconnect backoff
  backoff_max_seconds: 300
  queue_max: 1000                  # the bounded receive queue
  max_events_per_second: 50        # the per-source rate bound to the sinks
  batch_max: 100
  outcome_window_seconds: 300      # one outcome row per window
  max_event_bytes: 1000000
```

The first transport is **Server-Sent Events over HTTP**: it needs no new
dependency, goes through the same SSRF egress guard and TLS posture as every
poll, and is the one candidate whose protocol carries resume (the client
sends the last event id it processed as `Last-Event-ID`). A transport is one
module behind `runtime/stream_transport.py`; WebSocket and a NATS subject are
declared and refused at save until one is built.

**Who owns the connection.** Not the source actor (actors are woken by
reminders and deactivated when idle). A supervisor in the runtime host
(`runtime/stream_supervisor.py`, switched on by
`LEGBA_SUBSCRIBE_SUPERVISOR`, off by default) runs one connector per ACTIVE
subscribed head and follows the registry: pause or retire stops it, a new
head restarts it. Exactly one runtime replica holds a stream, through a
Postgres advisory lease per source.

**Restarts, resume and gaps.** The cursor (`actor_filter_state`) is the last
event id whose records were all written, persisted after each batch. A
reconnect sends the newest event already received; a restart sends the
cursor; the upstream replays from there and the content-hash collapse absorbs
the overlap. A connect that cannot resume (`resume: none`, events without ids)
after an earlier session is a **declared gap**: one `source_stream_gaps` row
(`no_resume`, from the last moment the stream was held to the reconnect).

**Bounded memory.** The receive queue holds `queue_max` events. A full queue
drops the arriving event and opens an `overflow` gap that counts every drop
until the queue accepts again. A drop is never silent: it is on the gap row
and on the window row. On shutdown, queued events are landed for a bounded
time; what is left is replayed on resume, or declared as a `shutdown` gap on
a stream that cannot resume.

**Health.** Each window row's `stream` column says what the connection did:
`connected` (events arrived), `quiet` (connected, keep-alives only — honest
quiet, carrying `newest_entry_ts` for the watchdog's discriminator),
`reconnecting`, `stalled` (no byte for the idle timeout; the connection is
dropped and reopened), `refused` (a 4xx, a blocked host, a missing
credential, a restrictive licence) or `stopped`. The health states and
outcomes follow the poll ledger's (`healthy` / `degraded` / `unhealthy`;
`success` / `empty` / `error`). The liveness watchdog adds one check a poll
does not need: `source_stream_down`, raised when a stream is refused, down
for three windows, or has written no window for three windows.

**Receipts.** Each received event's bytes, as they arrived, are a fetch
version (hashed, stored compressed, deduplicated) at the address
`<canonical stream url>#event=<event id>` (the canonical stream URL itself
for an event without an id), and every record parsed from it is linked to
it, so a streamed record's proof chain ends in the bytes Legba received, as a
polled record's does. A malformed event is kept too.

**First connect.** On any connect without a resume point, the kind's
first-poll age cap applies to the WHOLE connection (`stream_json`:
`first_connect_max_entry_age_days`, default 30, `0` = none): an upstream that
replays its history has every older entry skipped and counted
(`age_skipped`), exactly as a feed's first poll.

**Terms.** A subscribed source must declare `scope.license_class` (its
terms note; `unknown` is the honest reviewed-but-undetermined value). A
never-fetch class (`tos_restrictive`, `anti_ai_walled`, `personal_use_only`)
is refused at save, and the licence ledger is read on every connect, so a host
an admin marks restrictive is refused at the next reconnect.

## Source layers

A source's scope says what it covers; a **layer** says how a target should read it. This section
covers the source-layer table, the per-target aperture declaration, and the divergence measure that
reads them. The layers are defined per country, which is the example instance's subject shape.

A target can read its sources as a stack of LAYERS (the press split domestic and foreign, official and
state media, public data, a channel-level social digest, and a model-free physical/hazard layer) and
treat the CHANGE in that country's own layer-to-layer divergence as the finding, never the raw gap
(every country has one). A layer that is structurally absent is declared as such per target, so a
missing layer never reads as agreement.

### The three pieces

**The layer table** (`source_layers`, migration 0214) is PLATFORM x COUNTRY -> LAYER, curated and
versioned, with the reason each entry is in — curation IS the layer's bias, so an entry with no stated
reason hides exactly the judgement the table exists to make visible.

**The aperture declaration** (`desk_apertures`, migration 0214) is TARGET x LAYER ->
`{present, absent, unmeasured}`, per desk. `absent` REQUIRES a non-blank reason (enforced twice — the
pydantic model and a table CHECK, `desk_apertures_absent_needs_reason`); `unmeasured` is the honest
default nothing infers away. A loaded map always declares all six layers
(`registry/layer_map_schema.py`'s `LayerMapDescriptor` refuses a map missing one), so a layer with no
row for a target is *undeclared*, never the same thing as `unmeasured`.

**The retag generator** (`scripts/gen_layer_map_draft.py`) derives a first DRAFT layer table for one
country from what the existing `descriptors/source_*.yaml` already declare — `scope.geo`,
`scope.source_class`, `identity.kind`, and the wire/agency set in `descriptors/wire_map.yaml`'s
`same_publisher['ap']`. Every drafted entry carries `reason: "derived: <rule>"`; every drafted aperture
is `declared: unmeasured`. **The code never infers `present` or `absent`; a person curates.**

### The vocabulary

`src/legba/data/layers/_vocab.py:LAYER_VOCAB` (the migration's two CHECK constraints mirror it exactly):

| Layer | What it means |
|---|---|
| `official` | the target country's OWN government/primary-source publisher, or a state-controlled outlet read as that state's voice |
| `domestic_press` | independent/commercial press headquartered in and covering this country |
| `foreign_press` | international press, wire/agency dispatches, press not scoped to this country |
| `social_digest` | channel-level social monitoring — counts and summaries only, never identities |
| `public_data` | structured feeds: IGO/government open data, sanctions lists, conflict-event datasets, analytical output with no single-country scope |
| `physical` | model-free structured feeds (GeoJSON-style hazard/sensor data) — no editorial voice at all |

`APERTURE_DECLARED_VOCAB`: `present` / `absent` / `unmeasured`.

### Why a layer is not an origin class and not a source class

`origin_class` ([`data/provenance/origin.py`](../src/legba/data/provenance/origin.py), migration 0209)
says WHERE a row came from — live vs. seed vs. imported history. `SourceScope.source_class`
([`data/schemas/source.py`](../src/legba/data/schemas/source.py)) is the editorial tier a source
declares ONCE, platform-wide — reporting / analysis / official / state_media / claim. A LAYER is neither: it is
the COUNTRY-SCOPED READING of a source. The same `state_media` outlet is `official` for the country it
speaks for and, read from another desk, is a foreign state's messaging rather than that desk's own
official layer at all: the same channel is independent commentary in one country and the state's
voice in another. The three axes stay orthogonal on purpose.

### A worked example: one country's map

`descriptors/layer_map_il.yaml` (Israel, in the example instance) is the committed worked example. It started as the retag generator's
own output for `--country IL`, unedited, `identity.state: draft`, `map_version: layer_map_il.draft`,
every reason `"derived: ..."` and every aperture `unmeasured` — the shape below. It has since been
curated (`curate_il`): `identity.state: reviewed`, `map_version: layer_map_il.v1`,
every entry reasoned either `"derived: ... — confirmed"` or `"curated: ..."`, and all six apertures
declared for real (five `present`, one `absent` — IL has no dedicated official-class source; see that
aperture's own reason in the file). The DRAFT shape every generated map still takes, before curation:

```yaml
identity: {id, name, schema_uri, kind: layer_map, owner, created, state}
country: IL           # ISO-3166-1 alpha-2
map_version: layer_map_il.draft
entries:               # [source_id, layer, reason] — reason: "derived: ..." until curated
  - {source_id: source.jpost.frontpage, layer: domestic_press, reason: "derived: ..."}
apertures:              # every layer in LAYER_VOCAB, exactly once
  - {layer: official, declared: unmeasured, reason: ""}
```

`descriptors/layer_map_<cc>.yaml` is a distinct descriptor KIND from a `SourceDescriptor` —
`descriptors/source_*.yaml` stays reserved for sources
(`tests/data_pkg/test_source_class_taxonomy.py`).

### Loading a curated map

Nothing loads automatically. Once a person has turned a draft into a curated map (real entries,
real apertures, a real `map_version`):

```
PYTHONPATH=src LEGBA_DATA_PG_HOST=127.0.0.1 LEGBA_DATA_PG_DB=legba \
    python3 scripts/load_layer_map.py descriptors/layer_map_il.yaml --target country_watch_il
```

`--target` is the target this country's aperture half writes to (in the example instance
`country_watch_<cc>` / `country_g20_<cc>`, `runtime/target_resolution.py`'s convention), supplied by
the person loading it, never guessed: a country's layer table is a fact about its information environment, but
which desk reads it is a separate fact.

The load is idempotent and re-versioning: reloading an unchanged file is a no-op; editing content
without bumping `map_version` is refused loudly (`LayerMapVersionConflict`); bumping `map_version`
closes the prior open rows (`valid_until`) and opens new ones — nothing is ever overwritten in place,
the same discipline as `facts` / `nexuses` / `entity_edges`.

### The divergence measure (L2)

`deterministic_handlers/layer_divergence.py` is the unit that turns a loaded map into numbers and
findings — the one reader of these two tables. Per target country, over a 28-day window:

1. **counts** signals per layer per UTC day, wire copies folded to one *within* a (layer, day)
   bucket (`_layer_fold.py`; the same dispatch under `domestic_press` **and** `foreign_press` is the
   narrative-control pair's subject, not a duplicate, so the fold is never global);
2. **baselines** each pair of interest — `official`/`social_digest` (the regime–public gap),
   `domestic_press`/`foreign_press` (narrative control), `official`/`public_data` (the credibility
   gap) — as `log2((a+0.5)/(b+0.5))` against its own rolling 14-day median and MAD;
3. **fires** only when `|z| ≥ 2` on **two consecutive days with the same sign**, named `widening` or
   `narrowing`, severity from the z, confidence from the counts, with the day's top folded signals
   per layer as real citations. A layer under 5 items/day is `thin` and the finding says so.

The aperture binds it: an `absent` layer contributes **no count** and the finding states the
declared reason; `unmeasured` and `undeclared` are excluded and named; a pair with either side
excluded is skipped and the receipt says which side and why. When the map carries sources for a
layer the aperture calls `absent`, the suppressed count is reported under
`counts_suppressed_by_aperture` — the map and the declaration disagreeing is itself worth reading.

The series and the receipt ride `analyst_outputs.data` (no new table this round), and a run that
fires nothing is suppressed to trace-only, its receipt still landing in
`analyst_traces.output_payload`. `descriptors/analyst_layer_divergence.yaml` is the daily cadence
descriptor; the file ships `state: draft`, and the reference deployment's lifecycle overlay runs it
`active`.

**The classification error is not yet bounded.** A source filed under the wrong layer is a
*directional* error in every number above — it moves the gap one way rather than blurring it — and
no sampled audit has been run. That is [SEAMS #60](SEAMS.md), and `CLASSIFICATION_AUDIT_NOTE` is
stamped on every finding and receipt the unit writes so no reader can mistake an un-audited map for
an audited one.

### Reading it: the divergence map

`GET /api/v1/v3/layers/divergence`
([`registry/layers_api.py`](../src/legba/data/registry/layers_api.py)) is the one read surface over
this unit, and the `system.layer_divergence` panel ("Layer Divergence", Analysis —
[UI.md](UI.md#the-panel-catalog)) is its reader.

It serves the NEWEST receipt, desk by desk, plus each desk's newest FIRED divergence:
`{as_of, receipt_run_id, run_started_at, method_version, payload_schema, classification_audit,
window_days, baseline_days, z_threshold, mad_floor, consecutive_days, thin_min_per_day, layer_vocab,
pairs_declared[], desks: [{target_id, country, map_version, aperture, counts_suppressed_by_aperture,
layers{<layer>: {declared, reason, sources_mapped, thin_days, daily[]}}, pairs[…verbatim…],
fired | null}], desks_unresolved[], warnings[], target_id}`. `?target_id=<desk>` narrows `desks` and
`desks_unresolved` to that one desk (echoed in `target_id`); the receipt frame is unchanged, so an
empty `desks` beside a non-null `receipt_run_id` reads "the newest run did not measure this desk".

Two things about where it reads from. The receipt comes from **`analyst_traces.output_payload`**, not
from `analyst_outputs` — a run that fires nothing is suppressed to trace-only, so a surface reading
the findings table alone would be blank on exactly the days the instrument worked. The fires come
from the summary findings, and because this is a target-agnostic META analyst the rows carry no
`target_id` of their own: the desk lives inside `data.divergences[]`, and the route's `DISTINCT ON`
walks the unnested array (bounded by a `fired_days` window and a row cap).

The route computes **no statistic**. Every pair row — the series, the baselines, the
`no_fire_reason`, the excluded layers and the declared reason text — is passed through
verbatim; its whole arithmetic is turning the receipt's `daily` map into a day-ordered list. A desk
with no receipt is absent from `desks` and `receipt_run_id` is `null`, which the panel renders as
"no run yet" — a different fact from a run that measured nothing. `CLASSIFICATION_AUDIT_NOTE` rides
every response and the panel always shows it.

### What is not built

No registry lifecycle governs the `layer_map` descriptor kind — it is validated and loaded directly,
in the `descriptors/wire_map.yaml` tradition of a plain, hand-curated map. Nothing WRITES these
tables over HTTP: the read surface above is read-only, and `scripts/load_layer_map.py` remains the
only writer. The removal-as-signal sweep is a later program still.

## Declared gaps

The authoritative list is [SEAMS.md](SEAMS.md). The acquisition-relevant
entries: the `subscribe` mode's WebSocket and NATS transports are declared
and refused at save (only Server-Sent Events is built); eager media extraction is declared as a
modality-to-extractor registry with thin production handlers, so handlers attach
references and bytes are not fetched; and the per-host licence ledger ships
seeded with no verdicts, so a host stays at teaser depth — snippet landed, no
bytes archived — until an admin reviews it, which is a legal reading the
platform will not have a model make.

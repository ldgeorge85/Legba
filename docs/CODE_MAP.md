# Code map

Where each concern lives. One row per package or module family, with the job it
does and the file to start from. Every path here is a tracked path in this
repository.

This file answers "where is the code". For what the platform is and why it has
this shape read [ARCHITECTURE.md](ARCHITECTURE.md) and [ANALYSIS.md](ANALYSIS.md);
for the implementation rules read [DESIGN.md](DESIGN.md); for running it read
[RUNBOOK.md](RUNBOOK.md). What is built but not live is in
[SEAMS.md](SEAMS.md) and [STATUS.md](STATUS.md) — presence in the tree is not a
claim that a thing runs.

Cite code as `module.symbol`, never by line number: `grep` resolves a symbol and
it survives every split. This file carries no counts of modules or rows: they
move with every change, and `git ls-files` answers them from a checkout.

## 1. Top-level layout

```
src/legba/            the platform (Python package)
legba-ui-v3/          the React/TypeScript single-page UI
legba-models/         the model service (vLLM LLM + bge-m3 embeddings + NLLB/spaCy NER)
legba-media/          the media-extraction service (serves the media seam; 503s with no backend)
descriptors/          example source/target/analyst/pack/stack/discovery YAML, plus the lifecycle overlay (LIFECYCLE.md, LIFECYCLE.d/) and RETIRED.md
profiles/             instance profiles: profile.yaml manifests (geopolitics: today's descriptors/ + its prompts/legba_geopolitics package; a sanctions skeleton)
scripts/              registrars, seeders, backfills, measurement harnesses, ops shell
docker/               Dockerfiles (registry / runtime / worker / mcp) + Caddyfile + nats.conf
dapr/components/      Dapr component manifests (statestore, pubsub, secretstore, configuration)
deploy/               bring-up script, systemd units, cron lines, Prometheus rules, swarm stacks
seeds/                curated-dataset drop point (only the *.example.yaml files are tracked)
tests/                the test suite
docs/                 design and reference docs (this file)
docker-compose.yml    the whole stack, profile-gated
pyproject.toml        package metadata + console scripts
```

The package splits on one seam. `src/legba/data/` is the **declarative and
substrate** half: descriptor schemas, the registry, the handler libraries, the
store adapters, the migrations. `src/legba/runtime/` is the **execution** half:
the Dapr actor host, the four runtime planes, the reconcile loop.

The split is by responsibility, not by a hard import boundary. `data/` does
reach into `runtime/`, and almost entirely for one thing: an analyst kind
module imports the shared result and handler types from
`runtime/analyst_method.py`, which is why that module is kept a small leaf. The
handful of other crossings are named at their call sites.

### 2.2 `registry/` — the routers

`server.py` is the authority on what is mounted; it includes 35 routers. The
prefix column is the mount, not the route. Every JSON response the app serves
passes `display_class.py`'s `DisplayPolicyMiddleware` (mounted in `server.py`):
a reader-class caller gets `data/display_policy.py`'s projection — never
archived bytes or publisher text — and an admin's response passes through
untouched. `display_class.py` also decides the class (role stamp, then the
credential; an unplaceable caller is a reader) for the events socket and the
consult SSE relay, which apply the same policy themselves.

Every mounted route passes ONE app-level dependency, `route_roles.enforce_route_role`
(the leaf `route_roles.py`). With sign-in off it reads the earlier class table
`route_roles.ROUTE_ROLES` (`operator` / `reader-own-rows` / `read`); with
`LEGBA_AUTH_SIGNIN=1` it reads `route_policy.ROUTE_MIN_ROLES`, which names the
minimum role (`reader` / `contributor` / `admin`) of every mounted route and
refuses an unlisted one below `admin`. [API_ROLES.md](API_ROLES.md) is the
generated rendering (`scripts/gen_api_roles_doc.py --check` fails on a mounted
route with no entry).

Who the caller is: two pure-ASGI middlewares stamp the request state BEFORE
any dependency runs, and the role gate REFUSES a caller neither stamped on
every non-public route (X4 GATE — a route that forgets
`Depends(require_bearer)` is never open). `bearer_auth.py`'s
`BearerPrincipalMiddleware` (the OUTERMOST layer) is the one place a
request's `Authorization` header is read: it resolves the bearer (and the SSE
relay's `?token=`, the events socket's subprotocol) through `_deps.py`'s
resolvers — operator or fleet, both the `operator` class — and stamps
`principal`, `principal_actor`, `legba_role`, or records the 401/403/503 the
gate then answers. Next, `session_auth.py`'s `SessionCookieMiddleware`
resolves a signed-in USER's `legba_session` cookie (only when no bearer was
presented) through `data/users.py` and stamps `legba_role`, `legba_subject`
(the local user id) and `principal_actor = user:<id>`. The role gate and the
display class read those stamps; `require_bearer` / `_authorize_ws_token`
return the stamped actor. `session_auth.consult_owner_filter` confines a
signed-in user to the consult sessions they opened; `auth_state.py` keeps
the consult RUN owners (the SSE relay's owner check) and installs the
sign-in lockout's Redis store, both shared across processes.

## 5. Entry points, infra, descriptors, scripts

### Console scripts (`pyproject.toml [project.scripts]`)

| Script | Target | Role |
|---|---|---|
| `legba-registry` | `legba.data.registry.server:main` | The registry HTTP/WS API |
| `legba-runtime-dapr` | `legba.runtime.dapr_host:main` | The Dapr actor host |
| `legba-dapr-workflow-worker` | `legba.runtime.dapr_workflow.worker:main` | The durable-workflow worker |
| `legba-mcp` | `legba.ui.mcp_server:main` | The MCP server surface |

Migrations apply through `python -m legba.data.migrate` (`--dry-run` discovers pending files
without applying them, and is the only flag). A fresh deploy applies the shipped baseline
(`deploy/baseline/`) and then this runner applies the forward chain; `deploy/deploy.sh` does both.
The runner records each applied file in `legba_data_migrations(name, sha256, …)` and skips applied
files on a re-run, so a schema change is always a new migration file, never an edit to an applied
one. The substrate smoke check runs as `python -m legba.data.smoke` (`--json` for machine output).
The minimum environment to bootstrap the descriptor and stack registries is
`LEGBA_DATA_REGISTRY_DSN`, `LEGBA_DATA_MASTER_KEY` and the `LEGBA_DATA_DEFAULT_*` component ids;
`.env.example` holds the full list.

### Docker, Dapr, deploy

### `descriptors/`

Tracked YAML files by prefix: `source_*`, `analyst_*`, `target_*`,
`action_pack_*`, `layer_*`, `stack_component_*`, `discovery_*`, `template_*`,
`vocabulary_*`, `wire_map`, `collection_*`. `LIFECYCLE.md` (with notes under
`LIFECYCLE.d/`) records the states the reference deployment walks each file to,
and `RETIRED.md` the retired ids. The `collection_` prefix is
load-bearing rather than cosmetic: the source machinery globs
`source_*.yaml`, so a mis-prefixed holding would be activated as a live
feed.

The in-tree file is the pinned definition; the **live head** is whatever the
registry holds, and the two differ by design — activation is an admin's act
through the audited lifecycle route, so a descriptor that ships `draft` and runs
`active` is the intended path, not drift. The live analyst and source sets are
registry rows, not a directory listing: `ls descriptors/` undercounts sources
(the catalog registrar writes directly into `source_descriptors`) and
undercounts country desks (the desk registrars write targets directly). What is
where, by state in the tree, is in [STATUS.md](STATUS.md).

The analysis-spine descriptors are the ones to read first: the bounded units
(`analyst_leadership_transition.yaml`, `analyst_energy_security.yaml`,
`analyst_escalation.yaml`, `analyst_narrative_coordination.yaml`,
`analyst_internal_stability.yaml`, `analyst_military_posture.yaml`,
`analyst_economic_coercion.yaml`, `analyst_proliferation_watch.yaml`,
`analyst_disruption_status.yaml`), the composition tower
(`analyst_country_composition.yaml`, `analyst_region_composition.yaml`,
`analyst_world_assessor.yaml`, `analyst_escalation_composition.yaml`,
`analyst_escalation_dyad.yaml`, `analyst_hybrid_threat_composition.yaml`), the assessment channel
(`analyst_country_assessment.yaml`, `analyst_world_assessment.yaml`), the
deterministic indicator pair (`analyst_indicator_tracker.yaml`,
`analyst_collection_gap.yaml`), the measurement set
(`analyst_scorecard_producer.yaml`, `analyst_unit_correctness_scorer.yaml`,
`analyst_correctness_grader.yaml`, `analyst_reference_builder.yaml`,

## 6. Where to add a thing

| Goal | Add here | Then |
|---|---|---|
| A source kind | A handler module in `data/sources/` implementing the `_contract.py` Protocol | Declare the kind in `data/sources/kinds/` (or the `legba.source_kinds` entry point); write a `SourceDescriptor` |
| A declared type (principal kind, citation target, assertion type, alert kind, deterministic handler) | One module in `data/type_registry/<family>/` | [ADDING_A_TYPE.md](ADDING_A_TYPE.md) |
| An analyst kind | A module in `data/analysts/` declaring `KIND_NAME` (or a handler in `deterministic_handlers/` for a deterministic one) | Add the value to `AnalystKind`, or register it through the vocabulary; wire the run path in `runtime/analyst_method.py` and `runtime/analyst_deps_builder.py` |
| A deterministic sub-handler | A module in `data/analysts/deterministic_handlers/` | One declaration module in `data/type_registry/deterministic_handlers/` (nothing else is edited by hand; [ADDING_A_TYPE.md](ADDING_A_TYPE.md)); write the descriptor |
| A filter or enricher | A handler in `data/filters/` implementing the `StreamHandler` Protocol | Reference it from a source's `pipeline` |
| An output sink | A handler in `data/outputs/` implementing the `AlertEmitter` Protocol (plus a sub-sink in `alert_sinks/` for an alert surface) | Bind it through a target or analyst `OutputBinding` |
| A migration | A time-named `data/migrations/YYYYMMDDTHHMM_slug.sql` (UTC) | Apply with `python -m legba.data.migrate` |
| A predicate helper | `data/predicates/helpers.py` | Usable in source-selector and subscription Starlark |
| A provider adapter | A module under `data/stack/<family>/` | Register a `StackComponentDescriptor` |
| A discovery kind | A module in `data/discovery/` plus its materializer entry | Write a `discovery_*.yaml` |
| A curated seed source | An adapter in `data/seed/adapters/` implementing `SeedSource`, plus a dataset under `seeds/` (gitignored) | Register it in `data/seed/__init__.py` `ADAPTERS`; run `scripts/seed.py --source <name>` |
| A UI panel | A `.tsx` under `legba-ui-v3/src/panels/<area>/` | Register it in `panel-registry/registry.ts`, then re-run `scripts/gen_release_state_matrix.py` |
| A deliberately-not-built thing | Nothing in `src/` | Declare it in [SEAMS.md](SEAMS.md) with a guard rail that fails loud, and add its `file:symbol` line to the allowlist block |
